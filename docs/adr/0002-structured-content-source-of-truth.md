# ADR-0002: 構造化コンテンツを正本とし、HTMLを生成物とする

- Status: Accepted
- Date: 2026-07-30
- Decision Owners: Koo
- Related Specification: `SPEC-KB-001`

## Context

記事には次の長い情報が含まれる。

- 入力プロンプト
- 複数AIの回答
- 人間の考察
- 結論
- モデル・実行日などのメタデータ

記事HTMLを直接編集する方式では、次の問題が発生する。

- HTMLタグと本文が混在する
- AI回答のエスケープ漏れが起こりやすい
- Git差分が読みにくい
- テンプレート変更が全記事へ波及する
- 記事一覧データとの不整合が起きやすい
- AIエージェントが変更対象を誤りやすい

## Decision

`content/articles/`配下の構造化ファイルを記事の正本とする。

各記事を次のファイルへ分離する。

```text
article.json
conclusion.md
analysis.md
prompt.txt
responses/*.md
```

`articles/`配下のHTMLは生成物とする。

生成物だけを直接変更してはならない。

## Rationale

- 本文と表示ロジックを分離できる
- AIエージェントが変更対象を限定できる
- Git差分が明確になる
- 回答をエージェントごとに管理できる
- HTMLエスケープを生成処理へ集約できる
- テンプレート変更を全記事へ反映できる
- 記事一覧、sitemap、feedを同じ正本から生成できる
- JSON Schemaによる機械検証が可能になる

## Consequences

### Positive

- 記事の追加・更新を自動化しやすい
- 公開HTMLの一貫性が高まる
- 正本が明確になる
- 100件以上の記事を管理しやすい
- 将来的なテンプレート変更が容易になる

### Negative

- 生成スクリプトが必要になる
- Markdown変換処理の仕様を管理する必要がある
- 正本と生成物の両方をリポジトリへ保存する場合、差分が増える
- 生成処理を実行せずpushするミスが発生し得る

## Controls

- CIでサイトを再生成する
- 再生成後に差分が残った場合、CIを失敗させる
- `AGENTS.md`で生成物の直接編集を禁止する
- Pull Requestテンプレートで生成実行を確認する
- `article.json`をJSON Schemaで検証する

## Rejected Alternatives

### HTMLを正本にする

実装は最も単純だが、長期運用、AI編集、差分確認、安全性の面で不利である。

### 一つの巨大JSONに全記事を保存する

記事数増加時の競合と差分可読性が悪い。

### Markdown一ファイルに全情報を保存する

Front Matterと長い複数回答が混在し、エージェントごとの回答差分が確認しにくい。

## Validation

- 正本だけを変更してサイトを再生成できる
- 手作業で公開HTMLを変更する必要がない
- 同じ入力から同じ生成物が得られる
- 生成物と記事一覧の不整合をCIが検出できる
