# 3つのAI調査を、難しい言葉を減らして整理する

## 最初に分かったこと

3つのAIは、細かな数字ではかなり違う回答をしました。しかし、候補としてよく出てくる会社やモデルの系列は似ています。

- 安さと性能の候補としてDeepSeek
- 日本語や企業利用の候補としてQwen
- 長時間動くAIエージェントの候補としてGLM
- 安い大量処理の候補としてDeepSeekの高速系
- とても難しい仕事や大量の資料を読む候補としてKimi
- 追加候補としてMiniMax

ただし、ここで「DeepSeekが必ず1位」「Qwenが必ず安全」と決めるのは早すぎます。

## なぜ、そのまま順位を信じられないのか

### 同じ会社でも、比べている商品が違う

たとえば自動車で考えると、同じメーカーの軽自動車、SUV、スポーツカーを別々の人が評価し、その点数だけを平均して「このメーカーが1位」と言っているような状態です。

Qwenについて、3回答は汎用モデル、最大性能モデル、コード専用モデルを別々に選んでいました。値段も用途も違うので、同じ表で単純比較できません。

### 同じモデル名でも、販売店が違う

AIモデルは、開発会社の公式APIだけでなく、OpenRouterなど別会社の窓口からも使えます。

同じ商品でも、販売店によって次が変わるイメージです。

- 値段
- 速度
- 混雑しやすさ
- 一度に扱える量
- データをどこへ送るか
- 問題が起きた時の保証

そのため、「モデル名」だけでなく「どのProviderから使ったか」を必ず記録します。

### カードが使えるかは、公開ページだけでは分からない

日本のクレジットカードが使えるか、本人確認が必要か、最低いくら入金するかは、実際にアカウントを作らないと分からない場合があります。

AIのWeb調査で「使える」と書いてあっても、実際の契約画面で確認するまでは「条件付き」と考える方が安全です。

### 入力できる長さと、出力できる長さは違う

「100万トークン対応」と書かれていても、それは読める量かもしれません。1回で書き出せる量は、もっと少ない場合があります。

長いコード変更を任せるなら、次を分けて確認します。

- どれだけ読めるか
- どれだけ書けるか
- 公式APIの上限
- OpenRouterなど別Providerの上限

## 3つの回答で特に食い違ったこと

主な食い違いは次の通りです。

- DeepSeekで日本カードが使えるか
- DeepSeekが1回で出力できる最大量
- DeepSeekのJSON形式がどこまで厳密か
- GLMの値段と最大出力
- Z.ai海外版と中国向けサービスの契約条件
- Kimiで中国の電話番号やAlipayが必要か
- Kimiが実際に扱える最大の文脈
- Cursorで「動く」のか「公式に保証される」のか

これらは導入費用や安全性に直接関係します。都合のよい数字を選んで結論を出すべきではありません。

## では、どう進めるのがよいか

### 1. まず正式な商品名を確認する

各社の公式ページで、現在使える正確なモデルIDを確認します。「Qwenの最新」や「DeepSeekのPro」のような曖昧な名前ではなく、APIへ渡す名前を記録します。

### 2. 少額で同じ試験をする

最初はOpenRouterなど、複数モデルを同じ方法で呼べるサービスを使うと比較しやすくなります。

ただし、これは試食会の会場をそろえるためです。本番契約をOpenRouterに決めたという意味ではありません。

### 3. 実際に使う契約先でもう一度試す

候補を絞ったら、公式APIや固定したProviderで同じ試験をします。入口が変わると、速度や制限が変わる可能性があるからです。

### 4. 機密情報の扱いを決める

次を確認できないサービスへ、顧客情報や非公開コードを送らないようにします。

- どこで処理するか
- 何日保存するか
- 学習に使うか
- キャッシュするか
- 契約書やDPAがあるか
- 問題が起きた時に連絡が来るか

### 5. 合格点を先に決める

「なんとなく良かった」ではなく、たとえば次を決めます。

- 10課題のうち何件成功すればよいか
- 作ったコードがbuild/testを通る割合
- Tool Callingの正確さ
- JSONが指定形式を守る割合
- 1課題あたりの費用
- 人間が直す時間
- 429やタイムアウトの回数

## 私たちが採るべき暫定方針

現時点では、1つのモデルへ決め打ちするより、役割別に候補を残す方が合理的です。

| 役割 | 暫定候補 |
| --- | --- |
| 主力の価格性能 | DeepSeek系列 |
| 日本語・企業運用 | Qwenの現行国際向けモデル |
| 長時間エージェント | GLM系列 |
| 安い大量処理 | DeepSeekの低価格系列 |
| 難しい最終比較 | Kimi系列 |
| 追加比較 | MiniMaxの現行モデル |

これは採用決定ではありません。試験へ進める候補一覧です。

## 利点

- 1つのAI回答の間違いに引きずられにくい
- 価格だけでなく、契約や安全性も見られる
- 主力、補助、レビュー用に役割を分けられる
- モデルが終了しても切り替えやすい
- 実際の費用と人間の修正時間を比べられる

## 欠点

- 比較試験に手間がかかる
- 複数Providerの契約管理が必要になる
- モデルの更新が速く、結果が古くなりやすい
- 機密情報を扱う場合は法務・セキュリティ確認が増える
- 最初から「これが1位」と言う記事より結論が地味に見える

しかし、業務システムの導入判断では、派手な順位より、再現できる試験と説明できる契約条件の方が重要です。
