# AI時代の新規事業機会 — 探索軸の統合・追加発散

この回答は、独立した2本の他LLMブレストを入力として、既存A/B/Cを再定義し、重複を早く潰さず、因果関係の違いを残したまま探索軸を追加・整理したもの。市場成立を断定するものではない。

## 1. A/B/Cの再定義

- **A｜小さな需要を扱えるようになる** — 発見・開発・導入・運用などの提供コスト低下により、従来は事業化しにくかった小さな既存需要を扱える。
- **B｜新しい実行主体が、周辺需要を生む** — Agentが仕事を実行することで、実行管理・接続・権限・確認・責任などの新設・再設計が必要になる。
- **C｜人間判断を含む作業の分担が変わる** — 認識・読解・文脈判断の能力向上により、人間中心だった作業をAIとHumanの新しい分担へ組み替える。

A/B/Cは同一階層ではない。Aは採算条件、Bは需要の発生源、Cは実行可能性の境界を主に見ている。追加探索では **「何が分離して売れるか、何を束ね直せるか、何が失われるか、誰へ負担が移るか」** も問う。

## 2. 追加の探索軸 32個

### 01｜「仕事をする」前に、「委任できる状態」を売る

- **何が変わったか**：実行能力が高まるほど、仕事の定義不足、成功条件、禁止事項、例外条件の曖昧さが目立つ。
- **以前の壁**：業務整理や成功条件の明文化だけでは独立した購入対象にしにくく、SIやコンサルの前工程へ埋没していた。
- **成立の筋道**：実行そのものではなく、仕事を他者やAgentへ安全に渡せる状態を作ることが独立価値になり得る。
- **派生例**：成功条件の定義 / 例外・禁止事項の整理 / 入力情報の整備 / 委任範囲の設計
- **A/B/Cとの違い**：Cの作業代行より前にある、発注・委任の成立条件を扱う。
- **主な未知数**：共通化できる部分と個社固有部分、整備後に実際に委任できるか。

### 02｜情報ではなく「判断に必要な文脈」を供給する

- **何が変わったか**：同じ情報でも顧客・業界・過去の経緯によって適切な判断が変わり、その文脈をAIの入力として扱いやすくなる。
- **以前の壁**：文脈は社員の記憶や暗黙知に埋まり、持ち運べる商品になりにくかった。
- **成立の筋道**：情報量ではなく、情報をどう解釈するかを支える材料そのものを供給できる。
- **派生例**：業界慣習パック / 顧客別禁則情報 / 判断理由付き前例集 / 職種別Context Pack
- **A/B/Cとの違い**：作業実行ではなく、複数の実行者が使う判断材料を商品化する。
- **主な未知数**：有効な文脈の範囲、更新責任、顧客間で再利用できる割合。

### 03｜「答え」ではなく「確かめられる情報」を供給する

- **何が変わったか**：情報を使う処理が増えるほど、出所・取得時刻・適用範囲を確認できる入力の相対価値が上がる。
- **以前の壁**：個々の情報に検証可能性を付ける費用を回収しにくく、人間が必要時に調べ直す前提だった。
- **成立の筋道**：内容と一緒に、その内容を確かめる手掛かりを提供することで後続判断の信頼性を上げられる。
- **派生例**：原資料へ戻れるデータ / 取得時刻付き現況情報 / 適用範囲付き変更フィード / 検証済み一次情報パック
- **A/B/Cとの違い**：単なる収集代行ではなく、後続の判断が依拠できる入力を売る。
- **主な未知数**：鮮度、取得漏れ、出所確認と内容の正確性の違い、権利。

### 04｜運用の副産物を、別の産業の原材料にする

- **何が変わったか**：AIへの訂正、差し戻し、例外対応が記録として残りやすくなる。
- **以前の壁**：個別案件の処理で終わり、再利用可能な形へ構造化されていなかった。
- **成立の筋道**：本来の業務を回す過程で生じる記録を、検証・教育・学習・ベンチマーク等の別用途資産へ変えられる。
- **派生例**：例外データセット / 失敗事例集 / 受入試験素材 / 教育用ケース / 例外率ベンチマーク
- **A/B/Cとの違い**：Cの処理収益とは別に、処理の副産物から価値を生む。
- **主な未知数**：利用権、機密、匿名化、他社にも通用する情報か。

### 05｜作成時点の正しさではなく、「現行性」を維持する

- **何が変わったか**：文書・ルール・Agentが増えるほど、外部変化とのずれを追う対象も増える。
- **以前の壁**：作成後の妥当性確認が更新担当者の記憶や年次・月次見直しに依存していた。
- **成立の筋道**：成果物ではなく『今も使ってよい状態』を継続的に維持することを売れる。
- **派生例**：手順書の有効性監視 / 変更の影響先特定 / 古い判断条件の失効管理 / Agentと現実のドリフト監視
- **A/B/Cとの違い**：Aの定期配信を越え、情報と実際の利用先の依存関係を扱う。
- **主な未知数**：監視範囲、重要度判断、自動更新してよい範囲。

### 06｜記憶する能力ではなく、「使わない・忘れる能力」を売る

- **何が変わったか**：情報を保存・再利用しやすくなるほど、古い・誤った・不要な情報の影響も残りやすくなる。
- **以前の壁**：保存や検索の仕組みに比べ、利用停止・忘却は設計対象として弱かった。
- **成立の筋道**：保存・参照・再利用を止める条件や、情報の寿命を管理することを提供できる。
- **派生例**：期限付き記憶 / 誤った前提の参照停止 / 用途別情報利用制限 / 保存期限付き生成物
- **A/B/Cとの違い**：情報を増やすのではなく、情報が効かなくなる条件を設計する。
- **主な未知数**：複製先把握、完全削除の可否、停止状態の証明。

### 07｜各社に少量ずつ残る「難しい仕事」を束ねる

- **何が変わったか**：自動化が進むほど、通常処理とは性質の異なる難しい例外が残る。
- **以前の壁**：例外は各社の熟練者が通常業務のついでに処理し、独立需要として見えなかった。
- **成立の筋道**：各社には少量でも横断集約すれば、専門家待機や例外特化サービスを成立させられる可能性がある。
- **派生例**：業界別例外レビュー / 複数社共通の専門家待機 / 難案件振り分け / 例外キュー夜間レビュー
- **A/B/Cとの違い**：Cの残差を製品内に閉じず、残差側から市場を作る。
- **主な未知数**：例外の共通性、背景情報、集中発生時の処理能力。

### 08｜職務を分解した後に、「残った仕事」を再構成する

- **何が変わったか**：職務の一部をAI・外部サービスへ切り出せる。
- **以前の壁**：人を職務単位で雇う方が細かな分業を管理するより安く、残差の再設計が不要だった。
- **成立の筋道**：切り出したタスクだけでなく、残った人間タスクを新しい職務・共同運営・短時間専門職へ組み替えられる。
- **派生例**：複数社の残余事務共同運営 / 例外中心の新職務 / 短時間専門職の組成 / 人間工程の再配置
- **A/B/Cとの違い**：自動化率ではなく、雇用・外注・兼務の単位変化を見る。
- **主な未知数**：引継ぎ負担、責任のまとまり、働く側の持続可能性。

### 09｜「作れる能力」と「評価できる能力」を分けて育てる

- **何が変わったか**：一から作れなくても、生成物を選び、判断し、受け入れる役割を担える場面が増える。
- **以前の壁**：制作経験と評価能力を一体として育成してきた。
- **成立の筋道**：判断基準、典型的な誤り、受入判断を独立した教育・認定対象にできる。
- **派生例**：AI出力レビュー訓練 / 業界別評価ケース / 判断校正演習 / Agent運用者認定
- **A/B/Cとの違い**：人の作業を減らすのではなく、人が新しく担う判断役割を支える。
- **主な未知数**：実務への技能移転、評価者自身の誤り、認定の権威。

### 10｜AIによって「作り直さない方」が有利になる

- **何が変わったか**：既存コード・帳票・画面・運用の理解費用が下がる。
- **以前の壁**：中身が分からず、部分改修や延命を選びにくかった。
- **成立の筋道**：新しいものを作る能力を古いものの理解・仕様復元・部分置換・延命へ使える。
- **派生例**：レガシー仕様復元 / 部分的な接続追加 / EOL依存の段階除去 / 既存画面の意味的アダプタ
- **A/B/Cとの違い**：新規供給ではなく、既に持っている資産を使い続ける選択肢を増やす。
- **主な未知数**：復元理解の正確性、延命による負債先送り、検証範囲。

### 11｜AIによって「直さず作り直す方」が有利になる

- **何が変わったか**：仕様からの生成・検証・移行が十分に安くなる可能性がある。
- **以前の壁**：再実装の費用と失敗リスクが大きく、既存実装を守る方が合理的だった。
- **成立の筋道**：要求・検証条件・状態を資産として維持し、実装は交換・再生成可能な消耗品へ近づく。
- **派生例**：再生成可能な仕様資産 / 実装交換用受入試験 / 四半期再生成 / 生成前提のモジュール境界
- **A/B/Cとの違い**：Aの開発費低下をソフトウェア寿命と保守契約の変化まで進める。
- **主な未知数**：暗黙挙動、データ移行、回帰、生成品質の安定。

### 12｜退出や乗り換えを「実際に選べる行動」にする

- **何が変わったか**：データ移行、設定再構築、再実装を支援する費用が下がる。
- **以前の壁**：不満があっても切替作業の負担が選択を妨げ、ロックインが強かった。
- **成立の筋道**：新機能ではなく、既存選択をやり直せること・継続的に退出可能な状態を売れる。
- **派生例**：移行準備 / 解約時の持ち出し整備 / 継続的な乗換え準備 / SaaS切替一括支援
- **A/B/Cとの違い**：利用中の効率ではなく、顧客の選択可能性を変える。
- **主な未知数**：API制限、契約条項、データ以外の運用習慣・組織コスト。

### 13｜新しいものを売らず、既にあるものの稼働率を上げる

- **何が変わったか**：操作・設定・使い方の理解をAIが補助できる。
- **以前の壁**：購入済み機能を使える状態にする導入支援や教育が高く、現場が諦めていた。
- **成立の筋道**：新規導入ではなく、既存支出・既存機器・既存データから得られる価値を増やす。
- **派生例**：未使用SaaS機能活用 / 既存機器の使い方支援 / 眠っている社内資料の再利用 / Excelから既存SaaSへの橋渡し
- **A/B/Cとの違い**：新需要ではなく、購入済み資産の価値の取りこぼしを市場にする。
- **主な未知数**：使われない理由が操作難なのか、不要なのか。

### 14｜成果を売るための「測り方」を売る

- **何が変わったか**：処理記録・結果を取得して照合するコストが下がる。
- **以前の壁**：成果の定義と確認が重く、作業時間・席数・利用量で課金する方が簡単だった。
- **成立の筋道**：成果課金・成果保証を成立させるための測定、受入判定、未達分類を独立商品にできる。
- **派生例**：完了条件の定義 / 成功件数の照合 / 未達理由分類 / 成果課金の計測基盤
- **A/B/Cとの違い**：実行自動化ではなく、新しい取引単位を成立させる裏側。
- **主な未知数**：外部要因、双方が納得する定義、指標ゲーム化。

### 15｜性能ではなく、「失敗時の引き受け方」を売る

- **何が変わったか**：AIが実業務に関わるほど、成果だけでなく失敗時の対応が購入判断に入る。
- **以前の壁**：実行・確認・補償・復旧が一体化し、ソフトは原則責任を限定していた。
- **成立の筋道**：限定した範囲の修正・復旧・第三者確認・対応責任をラッピングして商品化できる。
- **派生例**：修正対応付き出力 / 復旧手順付き運用 / 第三者確認付き納品 / 限定補償付きAgent
- **A/B/Cとの違い**：『できる』より『何かあったときどうなるか』を変える。
- **主な未知数**：引受範囲、損害上限、確認可能性、保険との境界。

### 16｜事前防止とは別に、事後の「回収・訂正・復旧」を売る

- **何が変わったか**：誤りを含む処理が速く広く実行され、静かな失敗が後から発覚する可能性がある。
- **以前の壁**：誤処理対応は個別の調査・謝罪・修正で、共通機能になりにくかった。
- **成立の筋道**：発覚後の影響範囲特定、訂正対象抽出、再実行、関係者通知を独立サービスにできる。
- **派生例**：影響先追跡 / 訂正対象特定 / 再実行計画 / リコール相当の手続き
- **A/B/Cとの違い**：Bの事前安全部品より後にある、失敗した世界から戻す仕事。
- **主な未知数**：追跡範囲、取り消せない影響、訂正の二次事故。

### 17｜正しさではなく、「好ましさと一貫性」を供給する

- **何が変わったか**：一定品質の候補を多数生成できるほど、どれを採るかの選球眼が希少になる。
- **以前の壁**：編集方針や審美判断は制作作業と一体で提供されていた。
- **成立の筋道**：その人・組織らしい選択基準、避けるもの、世界観を独立して供給できる。
- **派生例**：ブランド編集方針 / 好みに合う候補選別 / 避ける表現の基準 / 『うちらしくない』検出
- **A/B/Cとの違い**：正解のある作業ではなく、主観的な選択基準を商品化する。
- **主な未知数**：好みの変化、再現範囲、コモディティ化。

### 18｜技術・制度・習熟の「進む速さの違い」を扱う

- **何が変わったか**：技術的に可能なことと、組織・制度・現場が実際に使えることの差が広がる。
- **以前の壁**：導入のつまずきは個別問題として処理され、移行段階自体は商品化されにくかった。
- **成立の筋道**：現在地から次の状態へ進む橋渡し、公式化、段階的権限拡大を売れる。
- **派生例**：Shadow AIの公式化 / 段階的権限拡大 / 運用手順移植 / 今年使える範囲の固定セット
- **A/B/Cとの違い**：技術不足ではなく、異なる主体の適応速度のずれを扱う。
- **主な未知数**：差が縮む速度、新しい技術変化で差が再発するか。

### 19｜言語の壁が下がった後に、「地域固有の適合」を売る

- **何が変わったか**：翻訳・説明の費用が下がる一方、商習慣・制度・期待品質など地域固有差は残る。
- **以前の壁**：地域知識へ到達する前に言語・営業・サポートの負担が大きかった。
- **成立の筋道**：翻訳そのものではなく、ローカル実務へ適合させる知識・運用を提供できる。
- **派生例**：海外製品の日本実務適合 / 地域固有の知識パック / 国をまたぐ実務調整 / 日本固有ノウハウの海外提供
- **A/B/Cとの違い**：情報処理効率より、地域間の違いを利用可能な橋にする。
- **主な未知数**：言語以外の障壁、地域知識更新、現地信頼形成。

### 20｜規則を「読むもの」から「行動条件」へ変える

- **何が変わったか**：規程・契約・方針を、実行時に参照する条件へ変換しやすくなる。
- **以前の壁**：人間向け記述と機械判断条件の間に個別実装・解釈が必要だった。
- **成立の筋道**：文書を納品するのでなく、行動を制約し、根拠を示し、変更時に再検査する状態を提供できる。
- **派生例**：業法Policy Pack / 社内稟議ルールの実行化 / 契約条件の自動適用 / 規程変更時のAgent再検査
- **A/B/Cとの違い**：Bの技術ACLだけでなく、人間社会の規範との接続を扱う。
- **主な未知数**：曖昧記述、規則衝突、法解釈、誰が保守するか。

### 21｜人間の判断を支援するより、「判断依頼の発生」を減らす

- **何が変わったか**：AIが提案・確認依頼・承認要求を大量に出せる。
- **以前の壁**：従来は依頼を作る側の能力が件数を自然に制限していた。
- **成立の筋道**：一件ずつ速く判断するより、委任条件を設計し、重複確認・不要エスカレーション自体を減らせる。
- **派生例**：同種判断の再利用 / 関連承認の集約 / 確認不要条件の設計 / 判断予算
- **A/B/Cとの違い**：Bの承認管理に対し、承認需要そのものを設計する。
- **主な未知数**：減らしてよい確認、例外見落とし、条件更新。

### 22｜自動化が失わせる「熟練への経路」を再設計する

- **何が変わったか**：初級者が経験を積んでいた日常作業をAIが担う可能性がある。
- **以前の壁**：日々の定型実務がそのまま練習機会を提供していた。
- **成立の筋道**：定型作業を人へ戻さず、熟練に必要な経験・失敗・判断だけを別の形で供給する。
- **派生例**：判断訓練 / 過去失敗の再体験 / 段階的に支援を減らす環境 / 例外ケース教材
- **A/B/Cとの違い**：人件費削減でも単なる教育自動化でもなく、技能形成経路の欠落を埋める。
- **主な未知数**：技能形成に必要な経験、実務移転、企業が残したい能力。

### 23｜自動化が消してしまう「観察機会」を取り戻す

- **何が変わったか**：入力・相談・確認を省くと、それに付随して見えていた異常や事情も消える可能性がある。
- **以前の壁**：情報取得が作業の副産物で、独立機能として設計されていなかった。
- **成立の筋道**：作業を人へ戻さずに、消えた観察窓・現場シグナルを再構成できる。
- **派生例**：顧客のつまずき回収 / 運用変更兆候の把握 / 非公式ルールの更新把握 / 人に聞かれなくなった質問の監視
- **A/B/Cとの違い**：削減する作業ではなく、削減によって失われる情報を見る。
- **主な未知数**：本当に失われる情報、監視過剰、活用責任者。

### 24｜最先端企業ではなく、「最も遅い接続先」を支える

- **何が変わったか**：一社の自動化が進んでも、取引先・委託先・行政・顧客など遅い接点で全体が止まる。
- **以前の壁**：参加者全体を同じ仕組みへ揃える調整が重かった。
- **成立の筋道**：全体を最先端へ移行させず、遅れている接点だけを意味変換・代理操作・受渡しでつなぐ。
- **派生例**：小規模取引先向け受渡し窓口 / 相手側導入不要の回答支援 / 非標準情報の引継ぎ / FAX/画面/電話の橋渡し
- **A/B/Cとの違い**：個社効率化ではなく、企業間の能力差による詰まりを扱う。
- **主な未知数**：誰が便益を得て誰が費用を負担するか、相手の協力負担。

### 25｜知能よりも、「正当にアクセスできること」が価値になる

- **何が変わったか**：分析・処理能力がコモディティ化しても、現場・情報・当事者へアクセスする権限は別に残る。
- **以前の壁**：能力とアクセス経路が同じ提供者内にあり、分離して商品化されにくかった。
- **成立の筋道**：同意・権限・現場への到達経路を、処理能力とは別に提供できる。
- **派生例**：同意済み情報取得網 / 正当な現地確認窓口 / 利用条件明確な専門資料 / 所有者側での限定処理
- **A/B/Cとの違い**：『処理できるか』でなく『触れてよいか、届くか』を見る。
- **主な未知数**：権限範囲・失効、仲介先依存、権利者への還元。

### 26｜AI利用者ではなく、「その活動を受ける側」を顧客にする

- **何が変わったか**：問い合わせ、提案、照会、予約要求など送信側の活動コストが下がる。
- **以前の壁**：相手側に発生する処理負担が送信者の費用へ反映されにくかった。
- **成立の筋道**：AIで活動を増やす人ではなく、その大量活動を受け止める人・組織を支援する。
- **派生例**：受付条件の明確化 / 照会の集約 / 処理量調整 / 必要情報をそろえてからの受渡し
- **A/B/Cとの違い**：BのAgent内部でなく、外部へ移された負担を扱う。
- **主な未知数**：必要連絡を妨げない方法、送り手との利害調整。

### 27｜成果物が能力の証拠になりにくくなると、証拠の作り方が変わる

- **何が変わったか**：見栄えのよい成果物を容易に生成できるほど、それだけでは本人の能力・遂行力を区別しにくくなる。
- **以前の壁**：成果物から制作過程や能力をある程度推定できる前提があった。
- **成立の筋道**：実行・説明・修正・条件変更への対応・再現を確かめる場そのものが価値になる。
- **派生例**：実演型能力確認 / 条件変更対応試験 / 過程を含む実績記録 / 再現可能な技能証明
- **A/B/Cとの違い**：偽物検出やAI利用検出ではなく、能力を示す指標を再設計する。
- **主な未知数**：測る対象、評価負担、公平性、実務成績との関係。

### 28｜個別の失敗率ではなく、「同時に失敗すること」に備える

- **何が変わったか**：多数の組織が同じモデル・情報源・基盤へ依存すると、共通原因の失敗が広がる。
- **以前の壁**：個別システム信頼性と、集団としての共通依存を分けて扱いにくかった。
- **成立の筋道**：共通依存の把握、異なる経路の確認、代替処理、縮退運転を商品化できる。
- **派生例**：異経路クロスチェック / 縮退運転 / 代替処理先 / 共通変更の影響マップ
- **A/B/Cとの違い**：Bの個体管理を越え、複数利用者にまたがる失敗構造を見る。
- **主な未知数**：何が本当に独立か、代替経路の同時混雑。

### 29｜導入効果ではなく、「戻せること」で行動を増やす

- **何が変わったか**：試作・複製・並行運用・移行確認の費用が下がる。
- **以前の壁**：試すことが、そのまま戻しにくい決定になる場合が多かった。
- **成立の筋道**：高性能な完成品より、小さく試し、途中でやめ、元へ戻せる条件を提供して採用行動を増やす。
- **派生例**：併走評価 / 限定委任 / 切替前再現環境 / 終了条件付き導入
- **A/B/Cとの違い**：性能や安さではなく、意思決定の不可逆性を下げる。
- **主な未知数**：戻せる範囲、試験と本番の差、外部への不可逆影響。

### 30｜「できるが、任せたくない」を商品条件にする

- **何が変わったか**：自動化可能範囲が広がるほど、本人が関わりたい部分を選べるようになる。
- **以前の壁**：自分で行う必要がある工程と、自分で行いたい工程が混ざっていた。
- **成立の筋道**：全代行ではなく、本人の達成感・選択・習得・関係性を残す支援を提供する。
- **派生例**：答えを出しすぎない学習支援 / 本人制作を残す趣味支援 / 家族の判断を代行しない調整 / Human-madeプレミアム
- **A/B/Cとの違い**：Cの逆方向で、人間の関与を意図的に残す。
- **主な未知数**：残したい工程、支援と介入の境界、希望の変化。

### 31｜AIをもっと動かすより、「十分なところで止める」を売る

- **何が変わったか**：案・処理・通知・改善提案をほぼ無制限に追加できる。
- **以前の壁**：作る費用が、追加しすぎを自然に抑えていた。
- **成立の筋道**：出力量ではなく、必要状態へ達したら止まり、人の注意・複雑さ・コストを増やさないことを価値にする。
- **派生例**：不要な再調査停止 / 候補数制限 / 余計な機能抑制 / 処理完了後の自動終了
- **A/B/Cとの違い**：BのCost Guardを越え、人の時間・注意・複雑さまで含む過剰供給防止。
- **主な未知数**：十分の判定、早すぎる打切り、停止理由の説明。

### 32｜代理人の能力ではなく、「誰の利益を優先するか」を売る

- **何が変わったか**：比較・推薦・交渉を代理人へ任せる範囲が広がる。
- **以前の壁**：検索・広告・販売・助言の利害が混ざっていても、最終選択は本人が担っていた。
- **成立の筋道**：高性能だけでなく、依頼者の条件・禁止事項・利益を優先していることを確認可能にする。
- **派生例**：選定根拠保存 / 利益関係の開示 / 本人の禁止条件維持 / 候補除外理由の確認
- **A/B/Cとの違い**：Bの実行権限ではなく、代理関係の目的と利害を扱う。
- **主な未知数**：忠実性の確認、希望が曖昧な場合、複数当事者の利害衝突。

## 3. かなり仮説的だが残す軸

### H1｜人間の「必要なときに呼べる能力」が独立商品になる

通常処理をAIが担い、人が必要な時刻・専門性・量を予測できるなら、作業時間そのものではなく『特定条件で人を呼べる状態』に価格がつく。例外レビュー待機枠、障害時判断支援、繁忙時確認能力など。未知数は同時需要と専門能力の代替可能性。

### H2｜製品ではなく「事業の運営構成」が随時生成される

販売、提供、確認、請求、支援などの機能を目的に合わせて短期間で組み替えられるなら、固定的な会社や製品でなく需要ごとの運営構成が商品になる。案件単位、季節限定、小共同事業など。未知数は責任主体と終了後資産。

### H3｜私有文脈を持ち出さず、「その場で処理する権利」を流通させる

個人や企業がデータを保持したまま限定処理だけ外部へ許可できれば、データ販売でなく『指定条件下で答えを得る能力』が商品になる。未知数は出力からの漏えい、処理証明、許可失効。

### H4｜実装ではなく「仕様・評価・対応責任」が流通する

実装を必要時に生成し交換できるなら、コードより望む挙動の定義、確認方法、問題時対応が中心資産になる。未知数は仕様に表れない期待、実装間同等性、長期再現性。

### H5｜商品が先に存在せず、需要の集合から商品が生まれる

代理人が希望条件と購入意思を整理し、他者需要と束ねられるなら、『この条件なら買う』集団が商品より先に形成される。未知数は購入意思の確実性、条件差、発注後離脱。

### H6｜小さな集団が、共通の知識や道具を育て続ける

調査・実装・更新・確認費が下がれば、一社が多数へ売る以外に、小さな利用者集団が必要資産を共同運営する市場が成立し得る。価値は独占より運営・検証・更新・参加調整。未知数は費用負担とガバナンス。

## 4. 軸同士の関係

### 4.1 「残り5〜10%」を一つにまとめない

AIが通常処理を担った後のHuman残差には、少なくとも別の市場がある。

```text
AIが通常処理を担う
  ↓
人間に難しい例外が残る
  ├─ 例外を処理する                     → 07
  ├─ 残った仕事を束ねて職務にする       → 08
  ├─ 判断・評価する人を育てる           → 09
  ├─ 訂正の記録を資産にする             → 04
  ├─ 人間への不要な判断依頼を減らす     → 21
  ├─ 失われた熟練形成の経路を補う       → 22
  └─ 必要時に人を呼べる能力を確保する   → H1
```

人間の処理負担は、単純な「例外率」だけでは決まらない。概念上は `対象件数 × 人間へ渡る割合 × 1件当たり処理工数 + 引継ぎ/確認工数` と考える方がよい。対象件数が増え、残る例外が難化すれば、例外率が下がってもHuman負担は同じ割合で下がらない。

### 4.2 「信頼」を一つの軸にまとめない

| 確かめたいもの | 独立して考える価値 |
|---|---|
| 内容が正しいか | 内容の検証 |
| 出所を確認できるか | 来歴・取得経路 |
| 今も使ってよいか | 現行性・鮮度 |
| この用途で使ってよいか | 利用条件・許可 |
| 実際に役立ったか | 成果の測定 |
| 本人に能力があるか | 実演・遂行の証拠 |
| 自分の好みに合うか | 編集・審美・一貫性 |
| 問題時に誰が対応するか | 引受範囲・復旧 |
| 自分の利益を優先するか | 代理関係の忠実性 |

### 4.3 反対方向の軸は、矛盾として消さない

| 同じAI変化 | 一方の機会 | 反対側の機会 |
|---|---|---|
| ソフト理解・生成が安い | 古い資産を延命する | 実装を作り直す |
| AIが作業を代行する | 人間作業を減らす | 技能形成を別に支える |
| 情報を保持しやすい | 記憶・文脈を資産化 | 忘却・利用停止を設計 |
| 顧客自身が作れる | 完成品購入を減らす | 自作物の検証・保守を売る |
| Agentが操作する | 操作UIを省く | 人間向け監督・説明面を強くする |
| 小さな提供者が増える | 供給が分散する | 共通の確認・接続・継続支援を集約する |

### 4.4 前段の軸も捨てない

今回の32軸だけで探索空間を置き換えない。先行ブレストにある、未実施需要の市場化、取引の小口化、需要の共同集約、短命ソフト、顧客所有、現実世界の確認・実行、参加型体験、Agent間取引、長時間実行、閉域処理、GUI労働の開放なども、独立した入口として raw source に残す。

## 5. より上位の分類案 — 三つの座標で持つ

### 座標1｜何の変化から機会が生まれるか

| 原理 | 問い |
|---|---|
| **実行可能性の拡大** | 以前できなかった何ができるようになるか |
| **採算・取引の閾値低下** | どのくらい小さい・短い・個別的な需要まで扱えるか |
| **活動量の増大** | 安くなった結果、何が多すぎるようになるか |
| **制約・負担の移動** | 次にどこが詰まり、誰へ負担が移るか |
| **分離と再集約** | 何を別々に売れ、何を新しく束ねられるか |
| **資産・権利の再定義** | 何を所有し、貸し、更新し、引き継げるか |
| **副産物の発生・消失** | 新しく何が残り、従来得られていた何が消えるか |
| **適応速度のずれ** | 技術・組織・制度・取引先の間にどんな差が生じるか |
| **選好の分化・反動** | 自動化できても、人は何を任せず、何を選び直すか |

### 座標2｜誰との関係で価値が生まれるか

利用者だけでなく、発注者、購入者、受信者、権利者、承認者、取引先、学習者、管理者、現場作業者へ主語を変える。同じ大量生成でも、作り手には生産支援、受け手には受付管理、購入者には選別、管理者には廃棄管理、権利者には利用条件管理として別市場が見える。

### 座標3｜需要はどの時間構造で発生するか

| 時間構造 | 機会 |
|---|---|
| **蓄積された未処理分を解消** | 既存資産整理、初期業務定義、過去データ整備 |
| **新しい導入のたびに発生** | 接続、権限、委任範囲、初期評価 |
| **利用量に応じて発生** | 例外処理、検証、実績確認、訂正 |
| **環境変化のたびに発生** | ルール、モデル、取引条件、担当者変更への追随 |
| **普段は使わず必要時に価値** | 復旧能力、待機枠、移行準備、代替経路 |

### 次回の探索軸テンプレート

```text
何が変わるという仮定か
  ↓
何が可能になり、何が増え、何が失われるか
  ↓
誰の、どの制約・負担・選択が変わるか
  ↓
何を分離して売る／束ね直す余地が生まれるか
  ↓
どの条件では、逆方向の機会も生まれるか
```

## 7. 探索の中心に置く問い

> **AIによって何が安くなるか。** その結果、**何が増え、何が消え、何が分離し、誰へ負担が移るか。** そして、その変化を受け止めるために、**新しく何を購入・所有・委任したくなるか。**

この問いから事業案を大量生成した後で初めて、市場規模、競合、価格、ユニットエコノミクス、MVP、Top 1を検証する。
