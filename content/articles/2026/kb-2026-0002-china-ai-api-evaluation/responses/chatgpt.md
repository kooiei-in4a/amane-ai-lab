## エグゼクティブサマリー

ChatGPT回答は、単純な性能順位ではなく、日本からの契約、リージョン、API互換性、運用性、データ管理を含めて評価しました。

主な判断は次の通りです。

1. **総合候補:** Qwenの国際・日本向け提供経路を、法人運用とリージョンの観点から高く評価。
2. **価格性能:** DeepSeekの高性能系列と低価格系列を有力視。
3. **長時間エージェント:** GLM系列をTool Calling、構造化出力、長いタスクの候補として評価。
4. **長文・マルチモーダル:** MiniMax系列を追加候補として評価。
5. **コード特化:** Kimiのコード向け系列を比較候補に含める。
6. **話題性:** Kimiの新しいフロンティア系列を高難度比較枠とする。
7. **Cursor:** 直接接続できる可能性と公式サポートを分け、Cline、Roo Code、Continue、OpenCode、LiteLLMの利用を推奨。
8. **機密コード:** モデル開発国だけでなく、Router、実推論ホスト、保存地域、ログ、学習利用、DPA、ZDRを確認すべき。

## API提供経路

回答は、初期比較と本番運用を分けています。

### PoC

OpenRouterなどの第三者APIは、複数モデルを同じ形式で比較しやすく、日本から少額で始めやすいと評価しています。

### 本番

採用モデルが決まった後は、次を再評価すべきとしています。

- 公式APIまたは固定Provider
- データ処理地域
- 保存期間と学習利用
- DPA、ZDR、SLA
- レート制限
- snapshotと廃止通知
- フォールバック時の送信先

## Cursorと周辺ツール

回答は、「OpenAI互換APIとして技術的に接続できる」ことと「Cursorが公式に保証する」ことを区別しています。

安定した比較経路として、次の構成を推奨しています。

```text
Cline / Roo Code / Continue / OpenCode
        ↓
LiteLLM または OpenRouter
        ↓
DeepSeek / Qwen / GLM / MiniMax / Kimi
```

独自Agentでは、Provider Adapterを用意し、PoCのRouterから公式APIや固定Providerへ切り替えられる構成を提案しています。

## データ・セキュリティ

特に次を注意点としています。

- モデル開発元とAPI提供元は別の場合がある
- 「学習に使わない」と「ログを保存しない」は別
- Prompt Cacheは保存期間を別に確認する
- Routerの自動ルーティングは送信先を変える可能性がある
- `latest`ではなくモデルIDまたはsnapshotを固定する
- 生成コードにはbuild/test、ライセンススキャン、人間レビューが必要

ChatGPT回答の最終提案は、1モデルへ決め打ちせず、次の役割へ分けて実API比較することです。

- 主力

PoCは統一APIで行い、採用後は公式APIまたは固定Providerで再試験する方針を推奨しています。
