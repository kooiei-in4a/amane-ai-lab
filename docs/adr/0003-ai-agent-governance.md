# ADR-0003: AGENTS.mdを共通のエージェント運用正本とする

- Status: Accepted
- Date: 2026-07-30
- Decision Owners: Koo
- Related Specification: `SPEC-KB-001`

## Context

本プロジェクトでは、複数のAIエージェントを利用して記事作成、メンテナンス、検査、レビューを行う。

利用候補には次が含まれる。

- Codex
- Cursor
- Claude Code
- GitHub Copilot
- その他のコーディングエージェント

各ツール固有の指示ファイルへ同じルールを複製すると、内容の不一致や更新漏れが発生する。

また、AIエージェントは効率的に作業できる一方で、次のリスクがある。

- 依頼範囲外の変更
- 生成物だけの修正
- 秘密情報の公開
- AI回答原文の無断編集
- 未確認情報の断定
- 記事IDやURLの変更
- 検証失敗を無視した公開

## Decision

ルートの`AGENTS.md`をAIエージェント向け共通指示の正本とする。

詳細ルールは`agents/`配下へ分離する。

```text
agents/
├─ policies/
├─ roles/
├─ workflows/
├─ prompts/
├─ schemas/
├─ checklists/
└─ examples/
```

ツール固有ファイルは、原則として`AGENTS.md`を読むよう指示する薄い入口とする。

## Rationale

- 共通ルールの重複を避けられる
- 複数エージェントで同じ運用契約を利用できる
- 変更範囲と停止条件を明確化できる
- エージェントによる自律作業を安全に拡大できる
- ポリシー、ワークフロー、役割を独立して更新できる

## Required Agent Behavior

エージェントは次を守る。

1. 作業前に`AGENTS.md`を読む
2. 対象作業に対応するworkflowを読む
3. 変更前に対象範囲を特定する
4. 正本を変更する
5. 生成処理を実行する
6. 自動検証を実行する
7. Git差分を確認する
8. セルフレビューする
9. 停止条件に該当した場合は作業を停止する
10. 実施内容と未解決事項を報告する

## Human Approval Boundary

次の操作には人間による明示的な許可を必要とする。

- mainへのmerge
- 公開済み記事の削除
- 記事ID変更
- 公開URL変更
- Git履歴の書き換え
- 秘密情報混入後の履歴修正
- ライセンス変更
- giscusリポジトリ・カテゴリ変更
- 外部スクリプト追加
- 大規模な全記事再生成
- セキュリティポリシーの緩和

## Consequences

### Positive

- エージェント間の運用差を抑えられる
- 自動化範囲を段階的に広げられる
- AIエージェントによる変更をレビューしやすい
- 作業手順がリポジトリ内で完結する
- 新しいエージェントを追加しやすい

### Negative

- ポリシー文書の保守が必要になる
- ルールが多すぎるとエージェントの探索コストが増える
- ツールによって`AGENTS.md`の自動認識方法が異なる可能性がある
- 人間の最終判断を完全には代替できない

## Controls

- `AGENTS.md`は簡潔な入口にする
- 詳細は`agents/`へ分離する
- 同じルールを複数ファイルへコピーしない
- ツール固有ファイルは参照のみとする
- workflowごとに停止条件を明記する
- レビュー結果にseverityを付ける

## Validation

- 異なるAIエージェントが同じ作業手順へ到達できる
- 正本と生成物を正しく識別できる
- 禁止操作を認識できる
- 自動検証失敗時に停止できる
- 変更内容を構造化して報告できる
