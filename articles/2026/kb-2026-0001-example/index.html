静的ナレッジベースの初期構成を複数AIで比較する

  • サンプル
  • 静的サイト
  • AIエージェント

結論

結論

静的HTMLと構造化正本の分離は、初期の公開ナレッジベースに適している。

  • GitHub Pagesだけで公開できる
  • AIエージェントが変更対象を誤りにくい
  • サーバーサイドアプリやDBは初期不要

主な制約は、管理画面がないことと、コメント機能を外部サービスへ依存すること。

考察・判断プロセス

考察

このサンプルは、実装パイプライン確認のための架空データである。

判断プロセス:

  1. 公開コストを抑える必要がある
  2. 記事差分をGitで確認したい
  3. AI回答のエスケープ漏れを防ぎたい

以上から、HTML直接編集ではなく content/articles/ を正本とする方式を採る。

制約・未確認事項

  • 実在の市場シェア数値は検証していない
  • コメントの読み込みと投稿にはGitHubへの接続が必要

訂正・更新履歴

  • 2026-07-30: サンプル記事を初版作成
  • 2026-07-30: giscusの本番設定を反映

入力プロンプト

あなたはソフトウェアアーキテクトです。
AIエージェントの検証結果を公開するナレッジベースを作ります。

要件:
- GitHub Pagesで公開する
- サーバーサイドアプリやDBは使わない
- 記事の正本と公開HTMLを分離したい
- AIエージェントが記事を更新しやすいこと

候補:
1. 静的HTML + 独自生成スクリプト
2. React / Next.js
3. 外部CMS

比較観点と推奨を簡潔に答えてください。
実在の顧客情報や秘密情報は使わないでください。

推奨は「静的HTML + 独自生成スクリプト」です。

理由:

  • GitHub Pagesと相性が良い
  • 依存関係が少ない
  • 記事ごとのURLが安定しやすい
  • AIエージェントがファイル単位で変更しやすい

React / Next.js は現状要件に対して過剰です。外部CMSは権限・料金・エクスポートの課題が増えます。
