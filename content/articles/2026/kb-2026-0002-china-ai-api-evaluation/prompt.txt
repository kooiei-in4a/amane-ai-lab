# 中国製AIモデルのAPI利用・開発用途調査

## 1. 調査目的

中国企業・中国系研究組織が開発したAIモデルのうち、API経由でプログラムから利用でき、ソフトウェア開発、コーディング支援、AIエージェント、業務システムへの組み込みに適したモデルを調査してください。

単なるモデル性能ランキングではなく、以下を判断できる実務的な調査結果を作成してください。

* 日本から現実的に契約・決済・利用できるか
* APIを既存プログラムへ組み込みやすいか
* Cursor、Cline、Continueなどの開発ツールや、OpenAI API互換クライアントから利用できるか
* コーディングやエージェント用途に適しているか
* 価格、性能、安定性、導入難易度のバランスがよいか
* 現在人気がある、または話題になっているモデルはどれか
* 一時的な話題ではなく、今後も利用候補として残りそうか

調査時点の最新情報をWebで確認し、古いモデル情報や過去の価格を最新情報として扱わないでください。

---

## 2. 調査対象

少なくとも、以下の開発元・モデル系列を調査対象候補に含めてください。

* DeepSeek
* Alibaba Cloud / Qwen
* Moonshot AI / Kimi
* Zhipu AI / GLM
* MiniMax
* ByteDance / Doubao / Seed
* Baidu / ERNIE
* Tencent / Hunyuan
* Huawei / Pangu
* 01.AI / Yi
* StepFun
* Baichuan AI

上記以外にも、調査時点で人気、話題性、性能、価格競争力のある中国製モデルがあれば追加してください。

ただし、次のモデルは主対象から除外して構いません。

* API提供が確認できないモデル
* 中国国内の特殊な契約が必須で、日本からの利用が現実的でないモデル
* 旧世代で、後継モデルに実質的に置き換えられているモデル
* 画像・動画・音声生成専用で、プログラム開発用途に適さないモデル
* 情報が極端に少なく、利用可否を検証できないモデル

除外した主要モデルがある場合は、除外理由を簡潔に示してください。

---

## 3. 「中国製」の定義

本調査では、以下のいずれかに該当するモデルを中国製として扱ってください。

* 中国に本社を置く企業が開発している
* 中国系企業グループが主要な開発主体である
* 中国の研究組織が中心となって開発している

APIの提供元が米国や第三国の事業者であっても、モデル自体が中国製であれば対象に含めてください。

---

## 4. API提供経路の区別

同じモデルでも、API提供経路によって価格、契約条件、データ管理、可用性が異なるため、以下を明確に区別してください。

1. 開発元の公式API
2. 中国国内向け公式クラウドAPI
3. 海外向け公式API
4. OpenRouterなどの第三者API
5. Alibaba Cloud、SiliconFlow、Together AI、Fireworks AIなどの外部ホスティング
6. セルフホスト可能なオープンウェイトモデル

公式APIと第三者APIは、原則として別行または別欄で比較してください。

「モデルの開発元」と「APIの提供元」を混同しないでください。

* 入力トークン価格
* 出力トークン価格
* キャッシュ書き込み価格
* キャッシュ読み取り価格
* Batch API価格

価格がコンテキスト長、キャッシュ利用、処理速度、優先度などで変わる場合は、その条件も説明してください。

* 請求通貨

* 本人確認・企業確認の要否
* 事前チャージ残高の有効期限

以下の観点で評価してください。

* コード生成能力
* 既存コードの修正能力
* 複数ファイルにまたがる変更能力
* リポジトリ全体の理解
* バグ調査
* コードレビュー
* テスト生成
* リファクタリング
* 長い指示への追従

* 指示からの逸脱の少なさ
* JSONなど機械可読出力の安定性
* 日本語での指示理解
* 日本語コメント・ドキュメント生成
* 英語中心の開発環境での性能
* 推論速度
* 初回応答速度
* 出力速度
* APIの安定性

以下の用途ごとに適性を評価してください。

* 独自のコーディングエージェント
* GitHub Issueからの自動実装
* コードレビュー
* CI失敗の分析
* 業務システムへのAPI組み込み
* 大量バッチ処理
* 低価格な補助モデル
* 高精度な主力モデル

### 5.6 Cursorでの利用可能性

「Cursorで使える」という表現は曖昧なため、以下を分けて確認してください。

* Cursorが公式にモデル選択肢として提供しているか
* CursorのCustom API Key機能で利用できるか
* OpenAI互換エンドポイントをCursorへ直接設定できるか
* CursorからOpenRouter経由で利用できるか
* Cursorでは直接使えないが、ClineやContinueなら使えるか
* LiteLLMなどのプロキシを介せば利用できるか
* Cursor内蔵モデルのバックエンドとして採用されている事実があるか
* 採用に関する情報が公式発表か、報道か、推測か

Cursorの内部モデル採用について、根拠のない推測を事実として記載しないでください。

* API入力データの保存期間
* 出力データの保存期間
* 学習利用の有無

* ログ保存の有無
* Zero Data Retention相当の選択肢
* データ保存地域
* 中国国内へのデータ移転の有無
* 海外向けAPIと中国国内向けAPIの違い
* DPAの提供有無
* 法人向けセキュリティ条件
* SOC 2、ISO 27001などの認証
* 商用利用条件

不明な項目は推測せず、「公開情報では確認できない」としてください。

## 6. 人気度・話題性の調査

人気度と話題性は別の指標として評価してください。

### 6.1 人気度

人気度は、実際の利用規模や継続的な支持を表します。

可能な範囲で以下を確認してください。

* API利用量
* OpenRouterなどでの利用順位
* Hugging Faceのダウンロード数
* Hugging FaceのLike数
* GitHubのStar数
* GitHubのFork数
* 関連リポジトリの活動状況
* モデル対応サービスの数
* Cline、Continue、Open WebUI、LiteLLMなどでの対応状況
* 企業での採用事例
* クラウド事業者での提供状況
* 開発者コミュニティの規模
* 継続的なアップデート頻度

### 6.2 話題性

話題性は、調査時点の直近3か月から6か月を中心に評価してください。

* 新モデル発表による注目
* ニュース報道
* X、Reddit、Hacker Newsなどでの言及
* 中国国内SNSや技術コミュニティでの反響
* ベンチマーク結果への反響
* 価格破壊としての注目
* オープンウェイト公開による注目
* Cursorなど著名サービスとの関係
* 大規模な資金調達や提携
* 障害、規制、セキュリティ問題など否定的な話題

### 6.3 評価方法

人気度と話題性を、それぞれ次の5段階で評価してください。

* 5：非常に高い
* 4：高い
* 3：中程度
* 2：限定的
* 1：低い

必ず評価根拠を併記してください。

単なるニュース件数だけで評価せず、実利用の裏付けを確認してください。

「公開直後で話題性は高いが、実利用はまだ少ない」など、人気度と話題性が異なる場合は明示してください。

### 6.4 トレンドの持続性

次の3段階で評価してください。

* 高：今後も主要な利用候補として残る可能性が高い
* 中：一定の利用は続くが、競合次第で存在感が低下する可能性がある
* 低：一時的な話題、または後継モデルに置き換えられる可能性が高い

根拠も簡潔に記載してください。

ベンチマーク結果を使用する場合は、以下を区別してください。

* 開発元による自己評価
* 第三者評価
* 静的な問題回答ベンチマーク
* 実際のソフトウェア修正ベンチマーク
* エージェント型ベンチマーク
* コーディング能力
* 一般推論能力

SWE-bench、LiveCodeBench、HumanEvalなど、評価対象が異なる指標を単純比較しないでください。

ベンチマークのスコアだけで推奨順位を決めず、APIの使いやすさ、料金、安定性、契約可能性も考慮してください。

## 11. 総合評価方法

各モデルを100点満点で評価してください。

* コーディング性能：20点
* エージェント・Tool Calling適性：15点
* APIの使いやすさ・互換性：15点
* 価格競争力：15点
* 日本からの契約・決済容易性：10点
* APIの安定性・運用性：10点
* 人気度：5点
* 話題性：5点
* トレンド持続性：5点

点数だけでなく、採点根拠を示してください。

確認できない項目を推測で高得点にしないでください。情報不足は減点または「評価保留」としてください。

## 14. 調査上の注意事項

* 最新情報をWebで確認すること
* 価格には確認日を付けること
* 公式APIと第三者APIを混同しないこと
* モデルの公開日とAPI提供開始日を混同しないこと
* 中国国内向けと海外向けサービスを混同しないこと
* チャット向け月額プランとAPI料金を混同しないこと
* オープンウェイトと無料APIを混同しないこと
* Cursorで直接使えるか、他ツール経由で使えるかを区別すること
* 人気と話題性を混同しないこと
* 開発元の自己申告ベンチマークだけで評価しないこと
* 未確認情報を推測で補完しないこと
* 複数の信頼できる情報源で重要事項を検証すること
* 情報源同士が矛盾する場合は、矛盾を明示すること
* 「中国製だから危険」「有名だから安全」といった一面的評価を避けること
