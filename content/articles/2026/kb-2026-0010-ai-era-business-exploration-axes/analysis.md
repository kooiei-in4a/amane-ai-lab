# 統合分析 — 次回も使える「探索の地図」

今回の成果は、単なるアイデア一覧ではなく、**新しい事業機会を発見するための探索原理のカタログ**として扱う。

他LLMの原文は `sources/llm-result-a.md` / `sources/llm-result-b.md` に全量保存し、ChatGPTの統合結果は `responses/chatgpt.md` に32軸 + 仮説6軸 + 関係整理 + 上位分類まで残している。本文では、それを次回の探索に使うための読み方を固定する。

## 1. A/B/Cは捨てず、格上げ・格下げする

- Aは「小さな取りこぼし」という適用先だけでなく、**採算・取引の閾値低下**という上位原理の一例と見る。
- Bは「Agent導入時の部品」だけでなく、**新しい実行主体が新しい故障・管理・責任・取引を作る**系統と見る。
- Cは「AI 90% + Human 10%」という比率ではなく、**認知・判断コストの低下で仕事の分解境界が動く**系統と見る。

A/B/Cへすべてを無理に分類しない。例えば、生成過剰、真正性、人間の注意、退出可能性、技能形成の欠落、受け手側の負担は、A/B/Cへ押し込むと探索理由が見えにくくなる。

## 2. 重要なのは「代替」だけではなく、制約の移動

AIが何かを安くすると、元の制約が消えるだけでなく、次の制約へ重心が移る。

```text
作るのが高い
  ↓ AIで安くなる
作りすぎる
  ↓
選ぶ・検証する・捨てる・止める・責任を持つ側が希少になる
```

同様に、

```text
Humanが通常処理をする
  ↓ AIが通常処理を担う
Humanは例外だけを見る
  ↓
例外が難化する / 判断依頼が集中する / 熟練形成の機会が消える
```

という二次・三次変化まで追う。

## 3. 「分離」と「再集約」を探す

従来ひとまとめだったものを、AIによって別々に売れる可能性がある。

- 実行 と 検証
- 通常処理 と 例外処理
- 制作 と 審美判断
- データ と 文脈
- ソフト利用 と 所有/退出権
- 能力 と 正当なアクセス権
- 実装 と 仕様/評価/対応責任

反対に、従来各社へ少量ずつ散っていたものを束ね直す余地もある。

- 各社の例外レビュー
- Human待機能力
- 分散需要の共同発注
- 小規模組織の共通知識
- 遅い接続先向けの共通橋渡し

## 4. 「失われるもの」を必ず見る

自動化は作業だけを消すとは限らない。その作業に副作用として付いていた価値も消える。

- 新人が経験を積む機会
- 顧客や現場の異常を観察する機会
- 人と人が関係を維持する接触
- 誰が責任者かという分かりやすさ
- 成果物から能力を推定する手掛かり

したがって、次回の事業案生成では「何ができるようになるか」だけでなく「何を失うか」から逆向きにも発想する。

## 5. 市場検証フェーズとの分離

このカタログは、意図的に市場性を確定していない。次フェーズでは各軸ごとに大量の事業案を出した後、別工程で反証する。

検証対象は少なくとも次。

- その変化は本当に起きているか / 起きる速度はどうか
- 既に人・予算・時間が使われているか
- 顧客は問題を認識しているか
- 内製・大手Platform・既存SaaSで十分ではないか
- 利用頻度と支払意思はどうか
- 提供側の運用負荷は低いか
- 権利・責任・規制上の壁は何か

## 6. 次回の使い方

次回はまず `responses/chatgpt.md` の9系列から2〜3系列を選び、各系列から20〜30案を**意図的に雑に**生成する。その際、Raw source も参照して、統合時に捨てた少数意見を復活させる。

案を出した後にだけ、Web検索・競合調査・反証・採点へ進む。

探索の第一問は次に固定する。

> 今回安くなった / 可能になった資源は何か。その結果、何が余り、何が足りなくなり、誰へ負担が移り、何を新しく購入したくなるのか。
